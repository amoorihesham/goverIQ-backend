# Data Model: Voting & Minutes

**Feature**: 005-voting-minutes | **Date**: 2026-05-17
**Input**: [plan.md](./plan.md), [research.md](./research.md)

All six tables this feature uses were created in the Phase 0 migration. This
feature applies **one additive migration** — a single `ADD COLUMN` on `votes` —
and otherwise alters no columns. This document maps each spec entity to its
existing table, records the one schema change, and specifies state transitions,
validation rules, and the audit write per operation.

---

## Schema Change — `votes.affirmative_option`

```ts
// src/db/schema/vote.ts — added to the votes table definition
affirmativeOption: text('affirmative_option').notNull(),
```

| Property      | Value |
| ------------- | ----- |
| Column        | `affirmative_option text NOT NULL` |
| Migration     | One additive `ALTER TABLE votes ADD COLUMN affirmative_option text NOT NULL` |
| Safety        | `votes` is empty until this feature ships — `NOT NULL` with no default is non-destructive |
| Generated by  | `drizzle-kit generate` (new migration file under the drizzle output dir) |
| Invariant     | Value MUST equal one of the strings in `votes.options` (enforced in `vote.service.ts` at creation; Zod cross-field refine catches it pre-DB) |

No other table or column is altered.

## State Transitions

### Vote status

```
OPEN ──close──▶ CLOSED        (terminal)
```

| From   | To       | Trigger        | Guard |
| ------ | -------- | -------------- | ----- |
| —      | `OPEN`   | create vote    | meeting status = `IN_PROGRESS` |
| `OPEN` | `CLOSED` | close vote     | current status = `OPEN` (guarded UPDATE); else `CONFLICT` |

Ballots are accepted only while `status = OPEN`; otherwise `VOTE_CLOSED`.

### Minutes status

```
DRAFT ──finalize──▶ FINALIZED  (terminal, immutable)
```

| From        | To          | Trigger    | Guard |
| ----------- | ----------- | ---------- | ----- |
| —           | `DRAFT`     | create     | meeting status = `COMPLETED`; no existing minutes for meeting |
| `DRAFT`     | `DRAFT`     | edit / attach resolution | status = `DRAFT`; else `MINUTES_FINALIZED` |
| `DRAFT`     | `FINALIZED` | finalize   | status = `DRAFT`; else `CONFLICT` |
| `FINALIZED` | `FINALIZED` | append correction | status = `FINALIZED`; else `INVALID_STATE_TRANSITION` |

A `FINALIZED` document's `summary`, `attendance_notes`, and resolution set are
immutable; only corrections may be appended (FR-417).

## Validation Rules

| Rule | Where enforced | FR |
| ---- | -------------- | -- |
| `options` has ≥ 2 distinct entries | Zod refine on create-vote body | FR-402 |
| `affirmativeOption` ∈ `options` | Zod cross-field refine + service check | FR-402 |
| Vote created only against `IN_PROGRESS` meeting | service | FR-401 |
| Explicit `eligibleMemberIds` ⊆ meeting attendees, non-empty | service | FR-403 |
| Null `eligibleMemberIds` → snapshot = current attendees | service | FR-403 |
| Ballot `choice` ∈ `vote.options` | service runtime check | FR-405 |
| Ballot caller ∈ `vote_eligibility` | service | FR-405 |
| One ballot per member per vote | `ballots_vote_voter_unique` index | FR-406 |
| Close only an `OPEN` vote | guarded UPDATE | FR-408 |
| Minutes created only against `COMPLETED` meeting | service | FR-412 |
| One minutes document per meeting | `minutes_meeting_id_unique` index | FR-412 |
| Edit / resolution only on `DRAFT` minutes | service | FR-414, FR-415 |
| Resolution vote ∈ same meeting AND `CLOSED` | service | FR-415 |
| Correction only on `FINALIZED` minutes | service | FR-418 |

## Audit Writes (8 events — all transactional)

Every event is written by `emitAudit(tx, …)` inside the **same** `withTx`
transaction as its originating write (FR-423, Constitution audit invariant).

| Operation                | Event                      | entityType | payload |
| ------------------------ | -------------------------- | ---------- | ------- |
| create vote              | `vote.created`             | `vote`     | `{ data: { question, optionCount, totalEligible } }` |
| cast ballot              | `ballot.submitted`         | `vote`     | `{ data: { voteId } }` — never the choice or member |
| close vote               | `vote.closed`              | `vote`     | `{ before: { status:'OPEN' }, after: { status:'CLOSED', outcome } }` |
| create minutes           | `minutes.created`          | `minutes`  | `{ data: { meetingId } }` |
| edit minutes             | `minutes.updated`          | `minutes`  | `{ before, after }` of `summary` / `attendanceNotes` |
| finalize minutes         | `minutes.finalized`        | `minutes`  | `{ before: { status:'DRAFT' }, after: { status:'FINALIZED' } }` |
| append correction        | `minutes.correction_added` | `minutes`  | `{ data: { correctionId } }` |
| export minutes           | `minutes.exported`         | `minutes`  | `{ data: { meetingId, format:'pdf' } }` |

Attaching a resolution emits **no** audit event (research Decision 13). The
`ballot.submitted` payload deliberately omits the choice and member to preserve
ballot confidentiality (FR-407) even in the audit log.

## Cross-Module Read (no schema impact)

The `meeting.service.ts` `IN_PROGRESS → COMPLETED` guard already counts
`votes WHERE meeting_id = ? AND status = 'OPEN'` using
`votes_meeting_status_idx`. This feature adds no code there — it only makes the
guard exercisable with real vote rows (FR-410).
